\head{Problem.} Command staff may receive the same event reports in different orders, with duplicate, delayed, or missing messages. One afloat node receives a report of an unidentified vessel near an exercise area, followed by a message identifying it as scheduled support traffic; a shore node receives those reports in reverse order. Conventional retrieval-augmented assistants process whatever each node has seen, so they can build inconsistent narratives even after the same reports eventually arrive. Event extraction from a centralized collection does not solve the additional problem of synchronizing evolving text-derived knowledge across disconnected nodes.
\par\head{Central hypothesis.} Representing extracted events as mergeable updates with explicit uncertainty and source identity will make distributed information fusion less sensitive to arrival order and improve the answers delivered under communication limits. We will test when nodes receiving the same evidence converge to a consistent event picture and how accurately they answer standing questions when communication is limited.
\par\head{Research plan.}
\begin{itemize}
\item \textbf{Extract updateable event facts, not overwritten summaries.} Turn messages into small event updates recording actors, places, times, relationships, corrections, and the underlying source. Maintain explicit alternatives when accounts conflict. Event identities and links will be revised conservatively as additional evidence arrives, so a late message does not silently erase a newer correction.
\item \textbf{Fuse reports independently of arrival order.} Design associative, commutative, and idempotent update rules for the symbolic event records, while studying the harder cases introduced by uncertain entity coreference and LLM extraction. We will measure when nodes receiving identical evidence converge and identify the conditions in which extraction ambiguity prevents convergence.
\item \textbf{Share information by its effect on live questions.} Express critical information requirements as standing queries over event knowledge. Under a limited channel, prioritize updates that change the answer, remove a high-impact contradiction, or narrow uncertainty. Each node will answer with traceable supporting reports and an indication of what it has not yet received.
\end{itemize}
\head{Evaluation and expected outcomes.} Multi-document event corpora built from KAIROS-style scenarios and \href{https://aclanthology.org/2022.emnlp-main.60/}{\textcolor{blue}{MAVEN-ERE}}, plus \href{https://proceedings.neurips.cc/paper_files/paper/2024/hash/e560a0b22e4432003d0dba63ff8dc457-Abstract-Datasets_and_Benchmarks_Track.html}{\textcolor{blue}{MEQA}} questions, will be partitioned across simulated nodes with message delay, duplication, loss, and reordering. We will compare graph agreement, query accuracy, delivery latency, and bandwidth against centralized extraction and last-writer-wins fusion.
\par\head{Naval relevance.} During distributed maritime operations, afloat and shore nodes may receive an unidentified-vessel report and its later identification in different orders. Updating the shared event picture using small, question-relevant messages would support a common tactical picture even across intermittent links. The framing aligns with the Command and Control portfolio's interests in uncertain, out-of-sequence information and automated integration across information stores.
